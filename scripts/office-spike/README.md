# Office clipboard spike

Measurement tools for hidden payload retention in Office pictures. All eight PNG, SVG and PDF
variants are ready in `packages/fixtures/office/carriers/`. This is a measurement protocol, not a
claim that Office preserves any carrier. JXA and PowerShell implementations still need native testing.

The payload digest is the SHA-256 of the inner JSON string, as returned by `checkEnvelope`, rather
than the hash of the envelope or carrier file. Generate carriers with:

```text
node scripts/office-spike/make-carriers.mjs --payload packages/fixtures/office/sample-document.json --svg packages/fixtures/office/sample.svg --png packages/fixtures/office/sample.png --pdf packages/fixtures/office/sample.pdf --out packages/fixtures/office/carriers --html packages/fixtures/office/sample.html
node scripts/office-spike/inspect.mjs packages/fixtures/office/carriers --json
node --input-type=module -e "import {readFileSync} from 'node:fs'; import {makeEnvelope,checkEnvelope} from './scripts/office-spike/payload.mjs'; console.log(checkEnvelope(makeEnvelope(readFileSync('packages/fixtures/office/sample-document.json','utf8'))).sha256)"
node scripts/office-spike/inspect.mjs saved.docx copied-back-directory --expect DIGEST_FROM_PREVIOUS_COMMAND --json
```

The default table includes file SHA-256, pixels/DPI, referencing document parts, carrier integrity
and expectation matches. JSON retains full errors. Comparing the file SHA-256 with `manifest.json`
distinguishes byte-identical media from changed media with a valid payload. An absent carrier has
an empty findings list; a malformed/unsupported carrier has an error. Inspection exits 1 on malformed
input, corrupt carriers, or expectation mismatch, and 2 on missing path arguments.

Use `--out <file>` to save the same TSV (or JSON with `--json`) as UTF-8 without a BOM,
with no stdout output and unchanged exit codes. For example:
`node scripts/office-spike/inspect.mjs saved.docx --out inspection.tsv`.
Use this instead of `>` in Windows PowerShell 5.1: redirection decodes Node's output through
the console code page and writes UTF-16, which can corrupt non-ASCII text.

ZIPs are read from their central directory (stored/deflate, CRC checked, at most 2000 entries and
200 MB inflated). ZIP64, encryption and multi-disk archives are refused. Input files are capped at
200 MB. DOCX/PPTX/XLSX media references resolve relative to each source part, including slide and
drawing relationship files, root-relative targets and XML/URI escapes; external targets are ignored.
Raw dumps are sniffed regardless of filename. Unknown blobs include first bytes in hex and a guess;
in particular an OLE/GVML blob is not assumed to be a ZIP. This tool does not decode proprietary GVML
or OLE storage. Entries under `media/` and `embeddings/` are inspected, including carriers stored
with `.bin` names. Undecoded blobs with an envelope marker report “marker present, container not
decoded”; that is evidence of a marker, not a verified payload. SVG inspection skips prologs and
resolves payload namespace prefixes with a bounded scan, without entity or DTD processing; an
unrecognised structure containing a marker reports “marker present”. PNG accepts `tEXt`, `zTXt`
and compressed or uncompressed `iTXt`. PNG decompression and each payload stream are capped at 20 MB.
Trailing NUL padding from clipboard allocations is accepted with a byte-count note for PNG, PDF,
ZIP, EMF and private JSON; non-zero trailing garbage still fails their readers.

PDF generation is append-only: classic xref tables, `/Prev`, preserved catalog/trailer keys, merged
`/Names` dictionaries and attachment trees. Inspection follows live catalog and name-tree references,
including indirect stream lengths. Xref streams (including hybrid xrefs), encryption and unsupported
payload filters are reported as errors. EMF inspection recognises our envelope only when a plain
`EMR_GDICOMMENT` starts at byte zero with `chemdraft` plus NUL followed by the UTF-8 envelope,
`chemdraft:BASE64` with raw-deflate encoding, or the bare `{"format":"chemdraft-spike"` envelope.
Markers elsewhere in comment data are ignored, including keywords inside encoded pictures;
`GDIC` and `EMF+` comments are parsed as binary containers. An unknown `chemdraft:` encoding is
reported as present but unreadable. Envelopes remain capped at 20 MB. No EMF carrier is
generated by this spike; supply one from a native producer when testing that format.

Nested pictures are inspected by their magic bytes. EMF `GDIC` / `EMR_COMMENT_MULTIFORMATS`
comments expose each `EmrFormat` after checking its table, `offData` and `sizeData`; the offsets are
relative to the comment identifier. `EMF+` comments expose Image objects containing compressed
bitmaps (PNG, JPEG, GIF, etc.) or metafiles. Continued Image objects are reassembled across records
and comments, with totals capped at 200 MB before allocation; invalid sizes, inconsistent totals,
overruns, broken continuation sequences and unfinished objects are errors. Pixel bitmaps and other
object types are skipped. Successfully extracted pictures use typed inspection without a duplicate
byte-scan row. RTF is recognised by its `{\rtf` prefix. Its `\pict` reader
records the blip kind (`\pngblip`, `\jpegblip`, `\emfblip`, `\wmetafile<N>`, `\macpict`, etc.)
and `\picw`, `\pich`, `\picwgoal`, `\pichgoal`, and decodes whitespace-separated hex or `\bin<N>`
bytes. Picture property destinations are skipped without interpreting their text as image data.

Each nested picture gets its own table/JSON row, retaining the existing column meanings: its byte
count and file hash describe that picture, and package references come from its enclosing media.
For example, `word/media/image1.emf > EMF multiformat[0] (PDF)` and
`public.rtf > pict[0] emfblip > EMF multiformat[0] (PDF)` can report
`pdf embedded file: valid; expect=true`. `--expect` checks nested envelopes too.

Unsupported containers (including WMF, flat RTFD, webarchive plists and OLE compound files) also
get a bounded byte scan for `%PDF` through the last `%%EOF` within a 20 MB window (ending before
the next PDF header), PNG signature
through `IEND`, and `<svg` through `</svg>`. The ordinary carrier reader validates each candidate.
These paths explicitly say **found by byte scan**, and JSON adds `foundBy: "byte scan"`; this is
carving evidence, not a claim to understand the surrounding container. RTF `wmetafile` pictures
also get this fallback when their bytes actually identify as EMF, so both parsed and scanned rows
can appear for the same payload. No proprietary storage decoder is used.

Container nesting stops at four levels, with at most 2000 nested entries and 200 MB of nested
inspection per input blob. EMF is capped at 100000 records and 256 formats, with a separate
100000-record cap for EMF+ across all comments. RTF is iterative,
capped at 256 group levels, 256 pictures, 100000 data spans per picture (200000 in total), 20 MB decoded per picture
and 200 MB decoded in total; sizes are checked before allocating decoded buffers. Byte scans cap
candidate counts at 128 and PNG chunk walks at 100000. Directory walks stop at four levels and
2000 paths. Truncation, odd hex, invalid offsets and exhausted limits are reported as errors.

## Manual matrix

Record the OS and Office build. On each of macOS and Windows, repeat each PNG, SVG and PDF
carrier in both Word and PowerPoint. Also test the combined clipboard set: private JSON, plain
text, HTML, PNG and DIB, PDF and SVG as supported by the platform. For each combination:

1. Write the intended clipboard flavors, then paste with ordinary Paste. In a separate trial use
   Paste Special and record the format selected. Save the document, quit the Office application,
   reopen it, and inspect the saved file. Record whether the media bytes are identical, whether a
   valid payload is present in changed bytes, or whether it is lost.
2. Save a separate copy after Compress Pictures, recording resolution and crop settings; quit,
   reopen and inspect it too. Copy the picture back from each saved version, dump every clipboard
   flavor, and inspect that dump for a recoverable envelope.
3. Repeat for the other host and platform. Record unsupported paste choices and errors instead of
   interpreting them as payload loss.

Office's choice of flavor, recompression threshold, and preservation of ancillary metadata are
measurements to establish, not assumptions made by these tools.

On macOS, write one item with multiple flavors and dump all items with JXA:

```text
osascript -l JavaScript scripts/office-spike/mac-pasteboard.js write packages/fixtures/office/carriers public.png=png-ztxt.png public.svg-image=svg-metadata.svg
osascript -l JavaScript scripts/office-spike/mac-pasteboard.js write packages/fixtures/office public.png=carriers/png-ztxt.png com.adobe.pdf=carriers/pdf-embedded.pdf public.svg-image=carriers/svg-metadata.svg dyn.ah62d4rv4gu80c6durvy0g2pyrf106p52fzv0u3prqv3gc3xyfz30n5dfqr4gw55sfrzhg55s=sample-envelope.json public.utf8-plain-text=text.txt public.html=sample.html
osascript -l JavaScript scripts/office-spike/mac-pasteboard.js dump /path/to/dump
node scripts/office-spike/inspect.mjs /path/to/dump --json
```

`public.html` takes the HTML file's bytes unchanged: JXA reads `NSData` and passes it directly to
`setDataForType`, without decoding or rewriting text. `NSPasteboardItem`, used by the JXA script,
refuses MIME-style names as “not a valid UTI string”. ChemDraft's native writer uses NSPasteboard
`setString`/`setData`, which accepts `application/x-chemdraft-selection+json` and stores it under
the dynamic type `dyn.ah62d4rv4gu80c6durvy0g2pyrf106p52fzv0u3prqv3gc3xyfz30n5dfqr4gw55sfrzhg55s`
plus the MIME name. The example uses that dynamic type to mirror what the app puts on the pasteboard.

On Windows, `-Write` accepts an array of `format=file` specifications; `CF_DIBV5` takes a PNG,
`CF_UNICODETEXT` a text file, `HTML Format` a UTF-8 HTML file, and `CF_ENHMETAFILE` an EMF. Paths can be absolute.
Run in Windows PowerShell 5.1 or PowerShell 7 on Windows, not PowerShell on macOS/Linux.
Under the default Restricted execution policy, first run `Set-ExecutionPolicy -Scope Process Bypass`
in that PowerShell session (or invoke `powershell -ExecutionPolicy Bypass -File scripts/office-spike/win-clipboard.ps1 ...`).
`HTML Format` builds a CF_HTML Version:0.9 header with CRLF lines and 10-digit zero-padded UTF-8
byte offsets. The input must contain ordered `<!--StartFragment-->` and `<!--EndFragment-->`
markers; offsets surround the fragment inside those markers. The reference builder
[`cf-html.mjs`](cf-html.mjs) is tested from Node and can also be run as
`node scripts/office-spike/cf-html.mjs packages/fixtures/office/sample.html output.bin`.
`CF_DIBV5` is a 124-byte BITMAPV5HEADER with top-down BGRA pixels, 32-bit BI_BITFIELDS,
explicit RGBA masks and sRGB, built through System.Drawing without a BMP file header. This is a
raster control: DIB conversion does not retain PNG metadata. `CF_ENHMETAFILE` uses
SetEnhMetaFileBits/GetEnhMetaFileBits rather than treating the handle as global memory. Unsupported
handle formats are listed in index.json with a note. Clipboard access retries ten times; a hidden
message-only owner window makes EmptyClipboard/SetClipboardData valid. `PDF`/`application/pdf` are
optional registered controls; whether Office accepts them must be measured.

```powershell
./scripts/office-spike/win-clipboard.ps1 -Write @('PNG=packages/fixtures/office/carriers/png-ztxt.png', 'image/svg+xml=packages/fixtures/office/carriers/svg-metadata.svg')
./scripts/office-spike/win-clipboard.ps1 -Write @('PNG=packages/fixtures/office/carriers/png-ztxt.png', 'image/png=packages/fixtures/office/carriers/png-ztxt.png', 'CF_DIBV5=packages/fixtures/office/carriers/png-ztxt.png', 'image/svg+xml=packages/fixtures/office/carriers/svg-metadata.svg', 'application/pdf=packages/fixtures/office/carriers/pdf-embedded.pdf', 'application/x-chemdraft-selection+json=packages/fixtures/office/sample-envelope.json', 'CF_UNICODETEXT=packages/fixtures/office/text.txt', 'HTML Format=packages/fixtures/office/sample.html')
# Requires an EMF carrier from a native producer; this spike does not generate one yet.
./scripts/office-spike/win-clipboard.ps1 -Write @('CF_ENHMETAFILE=C:\temp\carrier.emf')
./scripts/office-spike/win-clipboard.ps1 -Dump C:\temp\office-dump
node scripts/office-spike/inspect.mjs C:\temp\office-dump --json
```

Run `node scripts/office-spike/blank-docs.mjs <outdir>` (Node 22.2 or newer, for `zlib.crc32`) to create
`blank.docx` and `blank.pptx`, overwriting only those two files. Output is byte-identical only
within one Node/zlib build. Generate the files on the test machine itself; do not copy them from
a download, mail or network share. A copied file can open in Protected View, where Cmd/Ctrl+S
does not save in place. Open the existing blank file
in Word or PowerPoint before pasting (for example, `open -a "Microsoft Word" <outdir>/blank.docx`
on macOS), so Cmd/Ctrl+S saves in place without opening a Save dialog the test driver cannot use.

Both clipboard scripts require platform testing before relying on their output.

For each of the four PNGs, two SVGs and two PDFs first advertise that picture flavor alone,
then repeat with the full combined set above (substituting the carrier under test). Do not advertise
two variants of the same format in one trial. Check a write by dumping and inspecting before paste;
save each trial as a distinct DOCX/PPTX. Include both 96 and 384 dpi PNG trials, since Office may
recompress above roughly 220 ppi. Record the actual behavior rather than treating that threshold as
fixed. Private JSON, plain text, HTML and DIB are controls for flavor choice and copy-back, not evidence
that a picture retained its metadata.

## Fixtures and validation

The small native document contains caffeine and ethanol → acetaldehyde (a schematic oxidation, not
a balanced reaction). All three visible formats were rendered from that same document by the CLI;
render-document reported the caffeine, CCO and CC=O canonical SMILES with no export warnings.
The existing large native fixture is a grid of caffeine structures, approximately 296 KB.
`sample-envelope.json` wraps the small document for the private clipboard control; `text.txt` is its
plain-text control, and `sample.html` is the generated HTML flavor control. Fixture bytes stay below 3 MB.

The CLI `reaction` command exports SVG/PNG only. To obtain editable reaction objects the fixture
generation used its exported `renderReactionScheme('CCO>>CC=O', {conditions:'oxidation'})` function
in `packages/chemdraft-cli/src/commands/reaction.ts`, appended those objects to the existing native
caffeine document with translated coordinates, and then ran:

```text
pnpm -s chemdraft render-document --document packages/fixtures/office/sample-document.json --out packages/fixtures/office/sample --format both
pnpm -s chemdraft render-document --document packages/fixtures/office/sample-document.json --out packages/fixtures/office/sample.pdf
pnpm vitest run scripts/office-spike
```

In the isolated sandbox, the pnpm/tsx launcher could not open its IPC pipe; regeneration used
`node --import tsx packages/chemdraft-cli/src/cli.ts ...` with a temporary Node resolution hook
pointing missing third-party dependencies at the already-installed checkout behind `node_modules`.
The hook also resolved `@chemdraft/export-engine/pdf` to this worktree's source. It was removed after
generation; no dependencies were installed. The normal Vitest command could not write its bundled
temporary config through the shared node_modules symlink. The passing scoped fallback is:

```text
pnpm vitest run scripts/office-spike --configLoader runner
```

Tests cover every generated carrier and committed fixture, envelope tampering/bounds, PNG CRC/order,
PDF prefix/xref offsets and name-tree merging, DOCX/PPTX/XLSX relationship mapping, stored and deflated
ZIPs, malformed/oversized archives and payloads, and EMF comments. Native JXA/PowerShell execution
and the Word/PowerPoint matrix on macOS and Windows remain manual; Node tests do not verify those.
