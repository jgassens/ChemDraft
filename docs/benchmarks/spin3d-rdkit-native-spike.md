# Spin 3D — RDKit native embed spike (Phase −1)

**Date:** 2026-06-15 · **Branch:** `feature/advanced-3d-rendering`
**Purpose:** Decide whether to invest in a custom RDKit MinimalLib WASM embed engine by
first proving, on native RDKit, that ETKDGv3 embeds the offending molecule fast and
preserves specified stereochemistry. See the plan at
`.claude/plans/we-are-going-to-mossy-charm.md`.

## Why
Spin 3D's Fast/Balanced/Quality setting only gates the MMFF94 *minimise* stage. The real
cost is OpenChemLib's conformer **embed** (`ConformerGenerator.initializeConformers`,
rigid-fragment self-organization), which is mode-independent and untunable. Measured OCL
baseline for the molecule below: **~45 s** embed regardless of `maxTorsionSets` (10 vs
1000 identical); `getNextConformerAsMolecule` after init ~0 ms; MMFF94 `minimise` only
0.5–3.9 s. So the embed engine, not the refinement settings, must change.

## Environment
- RDKit **2026.03.3** (pip wheel `rdkit-2026.3.3-cp312-cp312-macosx_11_0_arm64`), Python 3.12, Apple Silicon.
- Embed params: `ETKDGv3()`, `enforceChirality=True`, `useExpTorsionAnglePrefs=True`,
  `useBasicKnowledge=True`, `timeout=10` (hard wall-clock rail). Seeds: `0xC0FFEE`, `42`, `7`.
- Script: `/tmp/rdkit_native_spike.py` (reproduce by re-running; SMILES embedded below).

## Molecule under test
64 heavy atoms, 74 bonds (~10 fused ether rings — a ladder polyether), **23 specified
tetrahedral stereocenters + 1 specified C=C**, 0 unspecified centers.

SMILES:
```
C[C@@H]1C[C@H]2[C@@H](C[C@]3([C@H](O2)C[C@H]4[C@H](O3)C(=CC(=O)O4)C)C)O[C@@H]5[C@@H]1O[C@H]6C[C@@H]7[C@](C[C@@H]8[C@@](O7)(C/C=C\[C@@H]9[C@@H](O8)C[C@@H]1[C@@H](O9)C[C@@H]2[C@@](O1)([C@H](C[C@H](O2)CC(=C)C=O)O)C)C)(O[C@@]6(CC5)C)C
```
The **exact molfile the Spin 3D handler sends** — produced via the real app paste path
(`insertSmilesMolecule` → `moleculeToMolfileV2000(mol, { fromDocFrame: true })`) — is saved
at `docs/benchmarks/offending-chemdraft.mol` and regenerated by the vitest test
[`apps/desktop/src/spin3dExactMolfile.test.ts`](../../apps/desktop/src/spin3dExactMolfile.test.ts).
It carries the 23 stereocenters as V2000 bond-stereo flags (1=up / 6=down). The native
spike embeds **this exact molfile** (`/tmp/rdkit_exact_spike.py`), not an RDKit proxy.

## Results — exact ChemDraft molfile

| Path | Embed time | Specified R/S | Specified E/Z |
|---|---|---|---|
| Exact molfile, seed `0xC0FFEE` | 1189.0 ms | 23/23 | 1/1 |
| Exact molfile, seed `42` | 612.4 ms | 23/23 | 1/1 |
| Exact molfile, seed `7` | 1337.4 ms | 23/23 | 1/1 |

RDKit perceives all 23 R/S + 1 E/Z directly from the molfile's wedge flags (the app's
serialization shape). Refine (on a good embed): MMFF94 `optimize(50)`=48 ms, `(200)`=162 ms;
UFF `(50)`=38 ms, `(200)`=140 ms (`rc=1` = not fully converged at that cap — fine for
depiction-grade geometry; per-mode caps apply).

**Atom mapping (original-index property, order-independent):** set on every input atom
*before* `AddHs`, read back after embed → `engineToOriginalAtom`. For the polyether, first
64 engine atoms are identity and all 70 RDKit-added H map to `-1`. **Explicit input H**
(verified on an alanine molfile with an explicitly drawn α-C–H): the input H keeps its
original index (stays mapped), while RDKit-added H map to `-1`.

**Unspecified stereo is never promoted (engine-agnostic):** the flatten layer's eligible
set is *only* centers the user explicitly specified
([`perspective.ts:361`](../../packages/chem-core/src/perspective.ts:361) — "Never invent
stereo just because the view has depth"; status `skipped-unspecified`). A center with real
3D handedness but no drawn wedge flattens to **0 stereo bonds / 0 promoted centers** —
locked by the existing passing test
[`perspective.test.ts:283`](../../packages/chem-core/src/perspective.test.ts:283). RDKit's
coordinates feed the same flatten path, so the guarantee carries over unchanged.

## Gate assessment — PASS
- ✅ Exact ChemDraft molfile embeds in **≤ 3 s** (0.6–1.3 s) vs OCL ~45 s (~30–70× faster).
- ✅ Specified R/S (23) and E/Z (1) preserved on every seed, perceived from the app's wedges.
- ✅ Atom mapping proven via atom properties, **including explicit input H**; added H → `-1`.
- ✅ Unspecified stereo not promoted through flatten/commit (design + existing test).

**Conclusion:** native RDKit ETKDGv3 is ~30–70× faster than OCL on this structure and
stereo-faithful end to end. Proceed to **Phase 0** (custom MinimalLib WASM exposing
`generate_3d_embed` + `optimize_3d_conformer`), then prep the turnkey patch/build package.
Headline number to reproduce in WASM: warmed embed ≤ 2–3 s in the real worker.
