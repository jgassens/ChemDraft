# 1.3 plan: several document windows, and resizable floating toolbars

Status: **draft for review** (2026-11-10). Nothing here is implemented. The base is `release/1.2-rc` at `a730d7af`.
The code facts below come from a read-only code map of that commit (openai-sol, agentctl run
`run-20261110-160634-532a31`). File references use `D/` = `apps/desktop/src/`,
`N/` = `apps/desktop/src-tauri/src/` and `C/` = `apps/desktop/src-tauri/capabilities/`.

The owner's scope for 1.3:

1. **Several document windows open at once**, on macOS and Windows (AGENTS.md §1).
2. **Resizable floating toolbars**: optional, and **off by default** behind a preference.

The two parts are independent. Part B is small and can ship first. Part A is large and has to be
built in layers, because almost everything outside the document itself assumes one window called `main`.

---

## 1. Where things stand today

- **One native document window, `main`, holding several document tabs.** It is declared in
  `tauri.conf.json:13` and created or restored by `N/lib.rs:1597` and `:1805`. There is no generic
  "create a document window" command and no registry of document windows.
- **Per-tab state already exists.** Each tab keeps its own history, file state, viewport, fragment
  selection and warnings in `documentTabSnapshotsRef` (`D/MainWindow.tsx:2496`). They are swapped by
  `snapshotDocumentTab` and `installDocumentTab` (`:9600`, `:9639`). Undo is per tab and stores whole
  snapshots (`packages/chem-core/src/history.ts`). This is the strongest asset: a document window
  can reuse it unchanged.
- **Everything native is wired to `main`.** That means 15 literal `main` / `dialog-main` uses, 71
  `MAIN_WINDOW_LABEL` uses across six Rust files, 18 `main` strings in TypeScript, and 20 capability
  files (15 of them are exactly `windows: ["main"]`). These cover quit, session load and save, menus,
  palette commands, dialogs, plugin panels, the clipboard owner, focus return, utility suspension,
  screen capture and performance probes.
- **One plugin runtime, but only by accident.** `usePluginRuntime` (`D/plugins/usePluginRuntime.ts:159`)
  creates one runtime per mounted `MainWindow`. A second document webview would create a second
  runtime, which violates AGENTS.md §4.2. A module-level singleton cannot be shared across webviews,
  because each webview has its own JavaScript realm.
- **One session file, one writer.** `document-session.json` (version 1) stores tabs and the active
  tab index, with no notion of windows (`D/documentSession.ts`). Rust lets only `main` read or write
  it (`N/lib.rs:3224`, `:3259`). Atomic rename prevents torn files, but not lost updates between
  competing writers.
- **Closing the Windows document window quits the app** (`N/lib.rs:1070`). On macOS the close button
  hides `main` and the app stays alive (`:1058`). Destroying `main` shuts down shared services:
  OCSR, naming, external tools and assistant MCP (`:1078`).
- **Toolbars are content-sized, with no saved size.** The native builder sets `resizable(true)`, but
  toolbars are undecorated, have no resize handles, and resize themselves to fit their content
  (`D/PaletteWindow.tsx:445`, `D/window-manager/index.ts:1108`). The saved state is `{x, y}` only,
  with no monitor or scale (`N/lib.rs:855`). Plugin panels already have a better frame model:
  monitor identity, logical size and destination-scale restore (`N/panel_window_frame.rs`).

## 3. Design, by topic

### 3.1 Per-window document state and undo

- `MainWindow` stays the document host. It is mounted once per document window, with an explicit
  **window id** (`doc-<uuid>`) passed in the route (`/?window=doc&id=…`).
- **No change to per-tab history.** Undo and redo stay per tab, inside their window. Undo labels
  (`WeakMap`, `:2874`) are already per component.
- **Identity becomes global.** Today's numeric `documentIdentityRef` and the literal first tab id
  `initial` are unique only within one window. Replace them with `{windowId, tabId, revision}`,
  where `tabId` is always a UUID. The plugin host's document key (`packages/plugin-host/src/index.ts:1351`)
  becomes this composite string, so a plugin write captured in window A can never land in window B.
- **Memory.** The 100-step history budget is per tab (`D/documentHistoryBudget.ts`). With N windows,
  add an app-wide soft cap: the coordinator reports total history weight, and windows trim their
  oldest steps first. Run this after T13; it is not needed on day one.

### 3.2 Window identity, creation and capabilities

- New Rust **`DocumentWindowRegistry`**: window id → native label, creation time, last-activated
  time, and lifecycle state (`creating`, `ready`, `closing`). Every place that resolves `main` today
  asks the registry instead:
  - `active_document_window()` — the last-activated document window, for menus, file opens and
    focus return;
  - `owner_of(label)` — for dialogs, panels and utility windows;
  - `all_document_windows()` — for quit, update and suspension.
- **Labels:** document windows become `doc-<id>`. The first window of a migrated session keeps the
  label `main`, so existing saved frames and tests keep working. New windows get new ids.
- **Capabilities:** add the document-window pattern (`doc-*` plus `main`) to the 15 `["main"]`
  capability files. Utilities never match it. Native checks that test `label == main` become
  `registry.is_document_window(label)` plus an ownership check. **Never drop a check; replace it.**
- **Creation:** one `create_document_window` command keeps today's window-creation serialization
  (`WINDOW_CREATION`, `N/lib.rs:1870`) and its main-thread rules. Each new window cascades 24 px from
  the active window and stays inside the monitor.

### 3.3 Menus on both platforms

- **macOS:** one app-wide menu, as today. Its target is `registry.active_document_window()`, which
  only document windows update. A palette, dialog or panel becoming key does **not** change the active
  document. Close Tab and Close Window validation (`:8381`, `:8400`) reads the active window's tab
  count.
- **Windows:** `install_app_menu` installs the menu on **every document window**, and never on
  utilities. This keeps the fix from the 1.2 crash (`N/lib.rs:7929`). Each window's menu reflects
  its own tab count and toolbar checks.
- **Routing:** `menu_command_target_label` (`:7538`) becomes "the document window that owns the
  source". On Windows that is the window the menu belongs to; on macOS it is the active document.
  Today's fallback to `main` is removed.
- **Validation:** the plugin menu snapshot and toolbar model (`:968`) become per window
  (`HashMap<windowId, Snapshot>`). macOS rebuilds the menu from the active window's snapshot when
  the active window changes.
- New items: **File ▸ New Window**, **Window ▸ (list of document windows)** on macOS, and **Window ▸
  Close Window** on Windows (Ctrl+Shift+W).

### 3.4 Palettes, panels and dialogs

- **Palettes (D5, D6):** one shared set. Every palette message gets a `target: {windowId, tabId}`.
  - Snapshots (active tool, style, command metadata) come from the active window only.
  - When the active window changes, the new active window re-broadcasts, and palettes re-render.
  - A preview, commit or cancel carries the target captured at gesture start; the owner window
    settles it even if it is no longer active.
  - Generic `listenTauriEvent` listeners that accept events for any target (`D/window-manager/tauriEvents.ts:91`)
    gain a target filter. Changing `emit` to `emitTo` alone does not isolate them.
- **Native ownership:**
  - Windows: utilities are owned (`owner_raw`) by the active document window, and are re-owned when
    the active window changes.
  - macOS: palettes are unparented today, so no change.
  - The shared `UTILITY_SUSPENSION` (`:1871`) becomes scoped to one window: one window's modal
    prompt suspends only that window's dialogs and panels, and suspends the shared palettes only
    while that window is active.
- **Plugin panels (D10):** the panel identity gains `windowId`, covering the label, saved frame key,
  report revision, staleness check and action routing (`D/plugins/panelBridge.ts:35`,
  `PluginPanelController.ts:43`). Closing the window closes its panels.
- **Dialogs (D7):**
  - `DialogCoordinator` takes its real owner id.
  - `dialogProtocol.ts:148` and `N/dialog_windows.rs:930` and `:1566` check the registry instead of
    `main`.
  - Labels become `dialog-<owner>-<kind>-<slot>`.
  - The duplicate check covers owner plus tab plus kind.
  - `dismiss_owned` (`:1905`) dismisses one owner's dialogs, not all of them.
  - Saved dialog positions stay keyed by kind.

### 3.5 Focus

- The registry tracks two things separately:
  - **native key window**: whatever the OS says;
  - **active document window**: the last document window to become key.
  Utilities never change the active document.
- Focus return (`focus_main_document_window_impl`, `:1718`; `panel_window.rs:152`; palette command
  return, `:6013`) goes to the **owner** of the palette or panel interaction, which is usually the
  active window.
- Focus leases (`panel_focus_lease.rs`, `pluginPanelInputFocus.ts`) keep their generation and epoch
  protection, unchanged. The pending-click guard (`palette_key_guard.rs`) records the active document
  window at click time, not `main`.
- **macOS hide/unhide** (`:5334`) restores the active document window. The invariant that `main` is
  never destroyed (`:5321`) is removed: `main_ns_window` becomes `ns_window(of: windowId)`.

### 3.6 Session restore and the single-instance lock

- **Session v2:**
  ```
  { version: 2, windows: [ { id, frame, activeTabIndex, tabs: [...] } ], activeWindowId }
  ```
  A version 1 file becomes one window. Unreadable tab envelopes are still kept as raw recovery
  entries, per window. The "Start with a fresh document" preference and the write guard (`:10471`)
  apply to the whole session.
- **Coordinator:** a Rust `SessionCoordinator` owns the file.
  - Each window sends its window snapshot with a monotonically increasing revision. The coordinator
    keeps the latest snapshot per window and writes the merged envelope through the existing atomic
    write.
  - It writes at most every 800 ms, and immediately on quit or update.
  - A closed window's entry is removed when it closes.
- **Restore:**
  - The coordinator reads once at startup and creates one document window per saved window, with its
    frame.
  - Each window receives **only its own tabs**; no window restores the whole session.
  - Hydration gating (queued file opens wait for restore) stays.
- **Single instance (unchanged process model):**
  - Windows: `tauri-plugin-single-instance` forwards a second launch's arguments to the running
    process. Its file opens go to the active document window (D4), or to the window that already
    holds the file (D3).
  - macOS: `RunEvent::Opened` behaves the same.
  - The single pending-open slot (`:742`) becomes a queue, so several files opened at once are not
    dropped.
  - The stable and dev app identities and locks (AGENTS.md §15.2) are untouched.

### 3.7 Close-window versus quit (both platforms), and keep-running on Windows

- Split `request_quit` from **`request_close_window(windowId)`** on both platforms.
  - **Closing any window, the last one included (D11, D12, D13):**
    1. The window settles its drafts, dialogs and plugin operations.
    2. It always asks about dirty tabs (D12).
    3. It sends a final snapshot to the coordinator, and **the coordinator flushes the session file
       to disk before the window is destroyed** (owner item c). So the session is current even if
       the app is later killed while running with no windows.
    4. Then the window is destroyed. Shared services, the plugin runtime host and the coordinator
       keep running.
  - **Quit** (File ▸ Exit, the tray Quit, ⌘Q, OS shutdown, the updater): the existing quit flow,
    generalized to all open windows (D15). With no windows open, quit only flushes and exits.
- **Running with no windows on Windows:**
  - **Tray icon (D17):** Tauri's tray API (`tauri::tray`, Windows only; built behind
    `#[cfg(windows)]` with a `cfg(not(windows))` no-op, per AGENTS.md §1). It is created when the
    last document window closes and removed when a window opens. Menu: New Window, Open…, separator,
    Quit ChemDraft. Double-click opens New Window. The icon and tooltip use the stable or dev app
    name (§15.2).
  - **Second launch and file opens (owner item b):** `tauri-plugin-single-instance` is already
    registered first (`N/lib.rs:913`). Its handler (`:2443`) opens the file in the front window or,
    with no window, creates a window. A plain second launch with no file creates a window. The
    pending-open queue (§3.6) covers opens during startup.
  - **Process lifetime:** `RunEvent::ExitRequested` with no windows is prevented unless the exit
    is an explicit quit (the same `APP_QUITTING` flag as today). Hidden helper webviews (the runtime
    host) never count as document windows.
  - **Windows shutdown and logoff:** the existing exit path flushes the coordinator. Test that a
    logoff with no windows open writes nothing new and loses nothing.
- **Updater and quit barrier (owner item d):** the barrier covers 0…N windows.
  - With no windows open, an update flushes the coordinator and installs.
  - With windows open, every window acknowledges its flush (each with its own timeout, keeping the
    two-second Windows teardown watchdog, `:435`) before the installer runs.
  - On Windows the update check also runs while there are no windows; its prompt opens a window
    first.
- Shared-service shutdown (`:1078`) moves from "main destroyed" to the application-exit path
  (`:1459`) only.
- **Ctrl+W keeps meaning "close tab"**, including the last-tab-becomes-fresh-tab behavior. Closing
  a window is the window's close button, Ctrl+Shift+W on Windows, or ⌘⇧W on macOS.

### 3.8 Plugin runtime ownership

- **Runtime host (D9):** a hidden webview `runtime` (route `/?window=runtime`) mounts
  `createPluginRuntime` once, owning the PluginHost, workers, installs and updates, panels, prompts,
  and the recognition, naming, external-tool and assistant controllers.
- **Broker:** a typed message protocol between the runtime host and document windows.
  - **Document provider calls:** `getDocument(windowId, tabId)`, `getSelection(...)`,
    `applyPatch(windowId, tabId, patch, label)`, and `undoOwnTransaction(...)`.
  - **Command invocation:** a document window invokes a plugin command with its captured
    `{windowId, tabId}`. Every capability call in that invocation uses that captured target, and
    focus changes never retarget it (today's rule: the document key is checked before a write,
    `plugin-host/src/index.ts:1221`).
  - **Contributions:** the host broadcasts menus, toolbar items, overlays and panels to every
    document window; each window registers them in its CommandRegistry as proxies.
  - The **assistant** history port (`D/assistant/historyPort.ts:31`, a module-level slot today)
    becomes a per-target port reached through the broker. Transactions stay bound to the tab
    captured at Send.
- **Canvas overlays:** each document window draws its own overlay, keyed by `windowId`
  (`PluginCanvasOverlay.tsx:134`, which falls back to `main` today).
- **Write scope (#364):** the scope check and the commit-time recheck run in the document window
  that commits. The broker carries the scope captured at command start.
- This is the largest single piece. It must land, with one document window, **before** a second
  window can be created.

### 3.9 Autosave

- Same 800 ms debounce per window. Snapshots go to the coordinator (§3.6), not straight to disk.
- Strict-mode flushes (update, quit) go through the barrier (D15).
- The serializer cache stays per window. Recovery behavior (unreadable entries kept, the
  kept-drawings flow) stays per window.

### 3.10 Resizable floating toolbars (Part B)

- **Preference:** `chemdraft.toolbars.resizable` (validated boolean, default `false`), shown as a
  Preferences ▸ Toolbars checkbox. Changes are broadcast live to open palettes (the existing pattern
  in `D/quitSettings.ts`).
- **When on:**
  - Palettes get the custom resize overlay and hit test that plugin panels already use
    (`N/panel_window.rs:586`, `:695`); there is no native frame. Edges and corners are resizable on
    both platforms.
  - A palette with a remembered size stops fitting itself to its content (`fitCurrentPaletteWindow`
    is skipped). Its body becomes a responsive viewport: items wrap in the grid, and it scrolls when
    smaller than its content.
- **Limits:**
  - Minimum: the larger of 96×56 (today's native minimum, `N/lib.rs:8764`) and one tool cell plus
    the title.
  - Maximum: the destination monitor's work area.
  - The Main toolbar may only be resized horizontally, since its height is one row by design.
- **Saving:** reuse the plugin-panel frame model (`N/panel_window_frame.rs`): monitor identity,
  monitor-relative logical x and y, and logical width and height. Store it under
  `toolbar-state.json` → `toolsets[id].frame` (a new optional field). The existing `{x, y}` stays,
  for older readers and for the preference-off case. Restore clamps to the destination work area and
  applies the destination monitor's scale.
- **Guards:** only a user resize gesture saves a size. Content fitting, DPI changes, a minimized
  owner, suspension, and quit never overwrite a remembered size (the same rules dialogs follow at
  `N/dialog_windows.rs:2839`).
- **Reset:** View ▸ Toolbars ▸ **Reset Toolbar Sizes** clears the remembered sizes.
- **Turning it off:** palettes go back to content fitting immediately. Sizes are kept, and used again
  if the preference is turned back on.
- **Downgrade safety (#340's rule):** the new `frame` field must never be added to a file that 1.2
  reads strictly. `toolbar-state.json` is read with a tolerant serde struct today, but add a test
  that 1.2's reader accepts a file written by 1.3. If it does not, put the field in a side file.

### 3.11 Moving tabs between windows (owner, D2)

- **Gestures:**
  - Drag a tab out of the strip and drop it outside any ChemDraft window: a new document window is
    created at the drop point, holding that tab.
  - Drop it on another window's tab strip: the tab joins that window at the drop index.
  - Also add Window ▸ **Move Tab to New Window**, a command and keyboard path, so moving tabs is
    accessible and testable without a drag.
- **What moves:** the complete tab state that `snapshotDocumentTab` already gathers (`D/MainWindow.tsx:9600`):
  - document history (past, present and future snapshots) plus the undo labels;
  - `NativeFileState` (path, dirty flag), the saved baseline (`savedDocumentsRef`) and save revision;
  - the non-pristine flag, viewport and scroll, fragment selection, warnings, and the
    imported-page-fit prompt;
  - **plugin selection and write-scope state, and proposal and assistant-transaction bindings**,
    retargeted from `{fromWindow, tabId}` to `{toWindow, tabId}`. The `tabId` stays the same, so
    bindings follow it.
  - the **palette target**: if the moved tab was active in the source window, the destination
    becomes the active window and palettes rebind to it.
- **"No copy and no re-parse"** (owner): the tab's state crosses between webviews as **structured
  data** (the chem-core documents and history are plain JSON-compatible objects). It travels through
  the coordinator in one message, using structured clone or JSON. It is **never serialized to CDXML
  or a file and parsed back**, and never re-opened from disk.
  - Exactly one copy exists at any time. The source removes its tab only after the destination
    acknowledges installation, and the two steps are made atomic by the coordinator (a two-phase
    hand-off: `offer` → `installed` → `release`).
  - Honest constraint: two webviews do not share memory, so the bytes are necessarily transferred
    once. What the owner rules out, a duplicate document or a re-parse, does not happen.
  - The undo labels' `WeakMap` is rebuilt on arrival from labels sent alongside the history.
- **Before a move, the source settles live state:** text, table and atom-label drafts are committed
  or cancelled (the same rules as `snapshotDocumentTab(..., settle)`). An in-progress gesture or
  palette preview is cancelled first. Open dialogs for that tab are closed, with their unsaved input
  discarded after a confirmation if any. Plugin panels bound to the source window keep acting on the
  source window. A running assistant request on that tab blocks the move, with a message ("Wait for
  the assistant to finish or stop it").
- **The last tab leaving a window:** the source window closes through the normal close path (§3.7).
  It does not ask about saving, because the tab is not lost, and the session removes the window.
- **Duplicate-file rule (D3) holds:** a move is not an open.
- **Large documents:** a move is bounded by the history budget (100 steps, weight 450,000) and
  takes one message. Measure it on the largest fixture; target under 200 ms for the drop.

## 5. Risks

1. **Edits landing in the wrong document.** Guarded by the composite identity (A1), the target
   captured at gesture or command start (A3, A5), and the write-scope recheck at commit time.
2. **Lost session data.** Guarded by the single coordinator with revisions (A6). Never have two
   writers.
3. **Breaking the one-runtime rule.** Guarded by the runtime host (A5) and a test that a second
   document window does not create a PluginHost.
4. **Shared services shutting down early.** Guarded by moving shutdown to application exit only (A7).
5. **Windows menu and focus crashes.** Never attach a menu to a utility window. Run
   `smoke:windows-menu-churn` with two document windows.
6. **Resize and DPI persistence.** Reuse the proven panel frame model and its guards. Never save a
   size from content fitting, minimizing or a DPI change.
